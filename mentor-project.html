MENTOR-LED PROJECT · AI ENGINEER

Build a workplace
knowledge assistant.

Sit beside a senior engineer: start with a real team problem, build a small retrieval-augmented assistant, inspect the evidence, and decide what must improve before a real launch.

Start without setup: try the browser retrieval lab. The project below is optional and runs on your own computer using fictional data and local models. Jump to Ollama setup.

01 · The team’s problem

Imagine the fictional Northstar service desk answers the same access, password, outage and equipment questions every day. Your team asks for a small assistant that finds relevant approved notes and helps staff answer questions.

Mentor’s first question: What if the assistant sounds confident but the notes do not contain the answer? A useful response must be checked against its evidence; the model should say when the evidence is insufficient.

FOLLOW THE DATA
Question + fictional notes
    → local embedding model converts text into vectors
    → cosine similarity ranks the notes
    → the two highest-ranked notes go to a local language model
    → model answer + retrieved notes → human evidence check

This starter searches vectors in memory; it is not a vector database. It re-embeds the small document set for each question. No application server or user account is needed.

02 · Set up your local workbench

Ollama runs models on your computer. This website cannot install, start or check it for you. The following steps are yours to run; this project uses local models and does not require an Ollama cloud account or API key.

Before you begin: You need a computer with sufficient free storage and memory, plus internet access for downloads. Model sizes and requirements can change; consult the model pages below. Windows installation requires at least 4 GB for Ollama itself, plus model storage. Leave additional space and memory for the models and your operating system.

Choose your operating system:

Windows · Download and open Ollama

Download and install from the official Ollama download page. Open Ollama, then open a new PowerShell or terminal window. See the Windows guide for requirements and support.

macOS · Download and open Ollama

Download Ollama from the official download page, install and open the app, then open Terminal. See the macOS guide for supported versions.

Linux · Install and start Ollama

Follow the official Linux installation guide for your architecture. Review installation commands before running them. Start the installed service, or run ollama serve in a terminal and keep it open while using the project.

  1. Install Python 3 if needed, then reopen your terminal. Run python --version (or python3 --version on some systems) and ollama --version. These check the commands are available, not that the model works.
  2. Check the local service by opening 127.0.0.1:11434/api/tags on the same computer. A JSON model list means the local API responded; an empty list is fine before downloads. If it does not respond, start Ollama. If needed, run ollama serve in a separate terminal; do not start a second server if one is already running.
  3. Review the model pages and licenses, then run both pull commands below. The downloads total roughly 1.6 GB at previously published sizes, but may change. Run ollama list and check that both models appear.
  4. Download mentor_assistant.py and test_mentor_assistant.py to the same folder. Open a terminal in that folder. If you already have this application folder, use its practice folder instead.
  5. Run the test and project commands below. The tests use a mock service: passing them does not prove a real model works. For the project command, check that an answer and retrieved sources appear, then compare the answer with those sources.
TERMINAL · DOWNLOAD THE MODELS
ollama pull nomic-embed-text
ollama pull llama3.2:1b
ollama list
TERMINAL · INSIDE THE PRACTICE FOLDER
python --version
python -m unittest -v test_mentor_assistant
python mentor_assistant.py "How do I request workspace access?"

On some computers use python3 instead of python; on Windows, py may also work. No extra Python packages are needed. First model loading may take time; smaller computers can run slowly or may not have enough memory.

Model details and licenses: nomic-embed-text and Llama 3.2.

Ollama or Python is not recognized

Finish the installation and open a new terminal. On Windows, try py --version; on macOS or Linux, try python3 --version. Check the relevant installation guide if the command is still missing.

The local API cannot be reached or the port is in use

Ensure Ollama is running on this same computer, then retry the API link. If ollama serve reports the address is already in use, do not start another instance; check the existing service and its configuration. This project expects 127.0.0.1:11434.

A model is missing, slow or cannot load

Check ollama list and retry the corresponding pull if needed. Check disk space, available memory and the model documentation. Downloads need internet, and local inference may be slow or exceed your computer's resources.

03 · Review like an engineer

  1. For the access question, inspect whether the [access] passage appears and supports each part of the answer. Record any missing or invented detail.
  2. Ask Where is the cafeteria? No supplied note answers it. Observe whether the model admits the evidence is missing; a small model may still invent an answer.
  3. Ask a paraphrase such as Who approves my workspace permission? Compare the top source with the first question. An embedding is a representation, not a guarantee of correct retrieval.
  4. Run the tests and change a fictional passage. Predict how this might affect retrieval, then run your questions again and record what actually happened.
Why does the program still show sources for an unsupported question?

Nearest-neighbor ranking always finds the closest available notes, even if none answer the question. A high score is not proof; a human must inspect the evidence and evaluate the response.

What is the difference between the two models?

nomic-embed-text converts the question and notes into vectors for ranking. llama3.2:1b generates an answer from the retrieved notes. Neither automatically verifies the answer.

04 · Your project handoff

Make a small table with each question, expected source or “no answer,” retrieved sources, model response, and whether the response is supported. Include both ordinary and misleading questions. Share your observations, not a claim that the assistant is production-ready.

Before a real deployment: add authorization, data governance, prompt-injection defenses, systematic retrieval and answer evaluations, citation verification, monitoring, privacy controls and a deployment review. This prototype does not implement these controls.

Privacy: use only the included fictional notes and non-sensitive questions. The Python program sends them to Ollama on 127.0.0.1; it does not call a cloud model or save questions. Ollama’s own configuration and logs are separate.
